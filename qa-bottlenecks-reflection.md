### Research & Learn

1. Why do QA bottlenecks happen in Agile teams?
- QA bottlenecks in Agile teams happen when testing, validation, and defect-resolution cannot keep pace with rapid development cycles.
- A QA bottleneck happens when testing becomes a slow point that prevents the team from finishing work on time.
This can happen when developers finish their work but testers have too many features to test at once, requirements are unclear, or bugs keep coming back for retesting.

2. How can testers avoid testing everything at the last minute?
- Testers can avoid last-minute testing crunches by shifting testing earlier in the lifecycle, prioritizing tasks based on risk, and integrating automation.
They can:
- Review requirements before development starts.
- Ask questions when something is unclear.
- Test features as soon as they are ready.
- Report bugs early so developers have time to fix them.
- Prioritise important features first.

3. What is parallel testing, and how does it help keep QA on track?
Parallel testing means testing different features or parts of an app at the same time rather than waiting for one task to finish before starting another.
For example, one tester could test Focus Bear's reminders while another tests focus sessions. This helps the team finish testing faster.

It can keep QA on track by:
- Slashing test execution time
- Preventing the "QA Bottleneck"
- Expanding test coverage rapidly

4. How do developers and testers collaborate to ensure smooth testing progress?
Developers and testers should communicate clearly, regularly and work together throughout the project.

For example:
- Testers ask developers questions when requirements are unclear.
- Developers tell testers when features are ready for testing.
- Testers report bugs with clear steps and evidence.
- Developers fix the bugs, and testers check the fixes.
- Both teams discuss problems early instead of waiting until the deadline.

5. What techniques can help QA work more efficiently without compromising quality?
Good QA is not about testing everything at the last minute. It is about planning ahead, working together, testing early, and focusing on the areas where problems would matter most.
Useful techniques include:
- Prioritisation: Test features that could cause the biggest problems first.
- Early testing: Start testing as soon as features are available.
- Automation: Use automated tests for repetitive checks where appropriate.
- Reusable test cases: Save test steps that can be used again.
- Parallel testing: Divide work among testers when possible.
- Clear communication: Report bugs early and explain them clearly.
- Risk-based testing: Spend more time on features that could seriously affect users.



### Reflection

1. If multiple features are ready for testing at the same time, how would you prioritize them?
I would test the most important features first, especially those that could cause serious problems for users if they fail.
For example, in Focus Bear, I would prioritise testing whether focus sessions start and stop correctly before testing a minor colour or design issue. I would also consider how many users could be affected and whether the feature is important for the app to work properly.

While interning at Assurdly and testing the Bank 78 app, the single-beneficiary transfer, bulk transfer, and scheduled transfer features were released at the same time. Although all three features were important, we prioritised testing the single-beneficiary transfer feature first because more users relied on it than on the other two features.

2. How can early involvement of QA prevent last-minute testing rushes?
QA testers can get involved from the beginning of a project by reviewing requirements, asking questions, and identifying possible problems before development is completed.

For example, while developers are building a new Focus Bear feature, I can prepare test cases and clarify how the feature should work. Once it is ready, I can start testing immediately instead of waiting until the entire app is finished.

3. What would you suggest to a team if QA keeps blocking releases due to late testing?
I would suggest that the team involve QA earlier, test features as soon as they are ready, and improve communication between developers and testers.
I would also recommend prioritising high-risk features, fixing bugs as they are discovered, and using automation for repetitive checks where appropriate.
